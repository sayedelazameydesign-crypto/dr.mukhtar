# مخطط بيانات وهمي محلي — مسودة فقط

## النطاق

- [`mock-data.schema.json`](mock-data.schema.json) مخطط JSON Schema draft-07 لشكل بيانات تجريبية
  مستقبلية؛ [`mock-data.fixture.json`](mock-data.fixture.json) عينة ثابتة لا تحتوي أسماء أشخاص
  أو أرقام هواتف أو روابط أو نصوص طبية أو أسرار أو معرّفات Google. لا ينفذ أي من الملفين كودًا،
  أو يقرأ بيئة التشغيل، أو يتصل بخدمة، أو يغيّر واجهة المستخدم أو Google Sheets/Apps Script.
- مسار `$schema` معرّف لمعيار المخطط، وليس نقطة اتصال للتطبيق؛ جميع `$ref` محلية داخل الملف.
  لا يلزم جلب المخطط من الإنترنت. لم يُضف محقق JSON Schema أو اعتماد جديد للمشروع.
- هذه البيانات **ليست** عقدًا للإنتاج أو بنية جدول `Requests`، ولا يُسمح باستيرادها إلى Google
  أو تعديل ترويسات الجدول وفقها. أسماء الحالات في المسودة تختلف عن القيم الحالية؛ أي ترجمة
  أو ترحيل يحتاج تصميمًا وموافقة منفصلة وجرد كل المسارات.

## نماذج مستقلة

- `appointments`: معرّف وهمي ومرجع ولي أمر وهمي فقط، وحالة موعد وفترة ونسخة ونص موافقة
  وهمي ووقتها. لا يوجد اسم أو هاتف أو نوع زيارة أو معلومات صحية. `version` رقم شكلي فقط،
  وليس آلية قفل أو مقارنة ذرية أو توقيتًا موثوقًا. نص الموافقة ثابت ووهمي؛ لا يمثل نصًا
  قانونيًا معتمدًا أو دليل موافقة شخص حقيقي.
- `reviewQueue`: إدخالات مراجعة تشير بمعرّفات وهمية للطلبات. وجودها لا يمنح إذنًا ولا يُجري
  موافقة أو حجزًا أو مزامنة. المثال يحتوي طلبين معلّقين للفترة نفسها عمدًا، بما يتوافق مع
  السماح الحالي بتعدد الطلبات المعلقة؛ لا يعني ذلك تأكيد الموعدين.
- `reminders`: حالة مستقلة عن الموعد، ولا يوجد نص رسالة أو `wa.me` أو جهة اتصال. في المخطط
  يرتبط `SENT_MANUAL` بعلامة يدوية وهمية؛ جميع الحالات الأخرى تتطلب `manualMark: null`.
  العلامة مجرد ادعاء من العينة وليست إثبات إرسال أو تسليم أو هوية موظف. تقييد إنشاء مسودة
  لتذكير موعد اليوم المؤكد، والموافقة اللازمة لذلك، متطلبات سلوكية غير منفذة هنا.
- صف `CONFIRMED` في المثال مجرد قيمة اصطناعية لا تثبت موافقة موظف أو إنشاء أو وجود حدث
  تقويم. لا يوجد إرسال أو رابط أو واجهة موافقة أو حجز حصري للفترة في الملفات.

## حدود التحقق والسلامة

المخطط يحدد مفاتيح مسموحة وأنواعًا وحدودًا وقيمًا وصيغًا نصية أولية. `additionalProperties: false`
لا يضمن خلو البيانات من معلومات شخصية إذا وضعها مستعمل داخل قيمة مسموحة؛ بادئة `fixture-`
ليست إثباتًا للوهمية. لا يُقبل استخدام بيانات حقيقية. تعبير التاريخ والوقت يتحقق من **الشكل فقط**؛
لا يثبت صحة التاريخ أو المنطقة أو انتقال DST. لا يتحقق المخطط من فرادة المعرفات، أو وجود
المرجع، أو الانتقالات بين الحالات، أو صحة الموافقة، أو الترابط بين حالة الموعد والتذكير، أو
التعارض، أو المصادقة والصلاحيات، أو سلامة كتابة/قراءة متزامنة. `UNKNOWN` لا يثبت أن حالة
حفظت أو أُغلقت؛ لا إعادة تلقائية أو تحرير أو حذف حدث بناءً عليه.

أي استخدام لاحق يحتاج محققًا مستقلًا معزولًا واختبارات إيجابية وسلبية لكل القيود، واختبارات
معنى وترابط وانتقالات وأعطال، ومراجعة الخصوصية وتوافق جميع مسارات الحجز. لا يوجد محقق
معياري مدمج في هذه المسودة أو تشغيل لها ضمن CI؛ قراءة JSON أو نجاح فحص محدود لا يثبت
صلاحية المسودة الكاملة أو حماية بيانات حقيقية. تبقى الجاهزية `not-ready` كما في
[الخطة المعمارية](../docs/ARCHITECTURE.md) و[تدقيق المسارات](../docs/composite-status-parity-audit.md).

فحص صياغة JSON محليًا دون شبكة:

```sh
python3 -m json.tool scripts/mock-data.schema.json > /dev/null
python3 -m json.tool scripts/mock-data.fixture.json > /dev/null
```
