# نماذج الخصائص ومدة التقديم — محلية وغير متصلة

## لقطة التقديم

`scripts/submission-snapshot-model.js` يقترح كائنًا وهميًا للمدة ومرجع الطلب وتاريخه ووقته
ونوعه ونسخة الإعداد. عند اختلاف المدة عند المطالبة يرجع `DURATION_DRIFT_REVIEW` دون كتابة أو
موافقة. حتى تطابق المدتين لا يفوض حجزًا. لا يحفظ الكائن ولا يثبت أصله أو سلامته، ولا يثبت أن
إعدادات التقديم بقيت ثابتة أثناء القراءة. يلزم تصميم تخزين وربط ومراجعة للتعديلات والبيانات
القديمة قبل تطبيقه. **لا تدمج المدة في حقل الوقت أو الطابع الزمني الحاليين**؛ تستخدمهما مسارات
قائمة بصيغ محددة. لا تُغيَّر ترويسات Sheets في هذه التجربة.

## خصائص السكربت

`scripts/properties-fault-model.js` و`scripts/test-properties-faults.js` يستعملان علامات
وقيمًا منطقية وهمية، لا `PropertiesService` ولا `Settings.gs`. النموذج يرفض الحجز وتقييم كل
من رمزي الاختبار عند تعذر القراءة، أو علامة تحديث غير مكتمل، أو سلامة إعداد غير مثبتة، أو تحديث
PIN غير محسوم. الوضع الاحتياطي هنا منع الحجز؛ لا يُفترض أن القيم الافتراضية صحيحة للعيادة.

العلامة الدائمة وفحص سلامة الإصدار وإبطال الجلسات **غير منفذة**؛ فشل كتابة العلامة أو عدم رؤيتها
قد يجعل قارئًا آخر يرى حالة مختلفة. لا تثبت المحاكاة رفض الرمزين في التطبيق الحالي أو إغلاق لوحة
الإدارة؛ لا تَعد بهذه الحماية قبل تصميم واختبار آلية قابلة للاسترداد، بما في ذلك انقطاع التخزين
نفسه. القيم المفقودة أو فشل الحصة تُعامل كقراءة غير معروفة، ولا يُنسب ذلك إلى إخلاء كاش تلقائيًا.
التحذير المعروض في البديل عام ولا يكشف قيمة سرية أو خطأ داخليًا؛ لم تُعدّل واجهة الموظف الفعلية.

تشغيل مستقل:

```sh
node scripts/test-submission-snapshot-model.js
node scripts/test-properties-faults.js
```

تُشغّل المجموعة أيضًا عبر `npm run test:safety-models`، ويستدعيها `npm test` و`npm run gates`.
كما يستدعي اختبار التسوية الموجود في CI المجموعة مباشرة؛ دون تغيير ملف سير العمل. إعداد CI
الحالي يعمل عند طلبات السحب والدفع إلى `main` أو التشغيل اليدوي، وليس على كل وسم Git تلقائيًا.
مرور الاختبارات ليس دليل تكامل Google، ولا إغلاق فجوة التزامن، ولا ترخيص تشغيل حي.

## فحص البروفة المتقاطع

`scripts/integrated-trial-audit-model.js` يجمع مشاهدات وهمية للطلبات وTrialNonces وخصائص
الإعدادات، ويستخدم عند توفرها مقارنة مدة التقديم/المطالبة وملاحظات Calendar الوهمية. اختلاف
أو غموض الأدلة يرجع حالة حرجة وتوصية بعزل عام أو نطاق أضيق مُثبت. حتى في لقطة تبدو متطابقة،
العلاقة بين nonce والطلب والنية غير مثبتة؛ النتيجة مراجعة بشرية وليست إذنًا للحجز أو الإصلاح.

الدالة **لا تُشغّل عند فتح لوحة الموظف**، ولا تحفظ حالة حرجة أو عزلًا أو سجل تدقيق، ولا تمنع
أي مسار حقيقي. حقول سلامة الخصائص والمدة افتراضات يقدمها الاختبار، وليست قراءة متزامنة أو
موثوقة أو مرتبطة بمعاملة واحدة. حالة `CONFIRMED` تحتاج تصميم دليل مدة مستقل، ولا يثبتها هذا النموذج.
أي مخطط تشغيل حي أو استعادة يقتضي تصميمًا منفصلًا لاختلاف القراءات والتزامن والاسترداد الآمن.

### اشتباه الانزياح الزمني

في المحاكاة فقط، إذا كانت مطالبة ممتدة صالحة أقدم من الحد الوهمي الذي يقدمه الاختبار، وشوهد
nonce مستهلك، وكانت مدة الخدمة الحالية المقروءة تختلف عن مدة المطالبة، تعود النتيجة
`LEDGER_TIMING_DRIFT_SUSPECT`. يطلب النموذج مراجعة بشرية ويمنع السماح بالتوافر والحجز والتحرير
والإصلاح والإعادة؛ كما يوصي بعزل عام أو نطاق أضيق مُثبت **دون حفظ أي عزل**. يجب على المستدعي
الوهمي تمرير الغموض إلى نموذج التوافر، كما في الاختبار؛ لا توجد وصلة كهذه في التطبيق الفعلي.

`claimObservedAtMs` وساعة الرصد والحد وفرضية تزامن الساعة بيانات اختبار اصطناعية. الصيغة المركبة
لا تحفظ توقيت إنشاء المطالبة، ولا يثبت حقل تحديث الصف توقيت المطالبة دون تصميم مستقل. اختلاف
المدة لا يثبت أن الإعداد تغير بسبب محاولة معينة، ووجود nonce لا يثبت علاقته بالطلب؛ فرق الساعات أو
تأخر القراءات قد يشوهان الترتيب. التاريخ المستقبلي أو الساعة غير الموثوقة يعيدان غموضًا حرجًا؛
والقدم وحده لا يحرر المطالبة مطلقًا. لا تحدد هذه التجربة مدة تشغيل آمنة حقيقية أو آلية مراجعة
أو تصريح تحرير بشري، ولا تستنفد جميع سيناريوهات الأعطال الممكنة.
