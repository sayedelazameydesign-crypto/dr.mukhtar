# مواصفة نظرية لبوابة بروفة معزولة — غير منفذة

لا يضيف هذا المستند `doPost`، ولا ينشئ مشروعًا أو جدولًا أو تقويمًا، ولا يجيز النشر أو
الاتصال بـGoogle. الوضع الحالي غير متوافق: `scripts/probe-composite-paths.js` يفحص كود GAS
ببدائل محلية ويعيد 1. نجاح النماذج لا يثبت تغطية 100% أو سلامة البروفة المستقبلية.

## العزل والتفويض

- يلزم مشروع Apps Script مستقل وSheet وCalendar اختبار مستقلان وصلاحيات محدودة؛ Deployment
  مختلف في المشروع نفسه لا يعزل Script Properties أو Script Lock. لا تُستخدم بيانات مرضى أو أصول
  الإنتاج، وأي تشغيل حي يحتاج موافقة منفصلة.
- يمكن اقتراح JSON في `e.postData.contents` يتضمن nonce وطابع العميل وحمولة وهمية. **nonce ليس
  رمز مصادقة**؛ الحقول الثلاثة المقترحة وحدها لا تفوض أحدًا. يلزم تصميم منفصل لمصادقة محدودة
  وصلاحياتها وتجديدها وسحبها، دون أسرار في URL أو سجلات أو أمثلة حقيقية. لا يفترض هذا المستند
  إمكانية قراءة ترويسات تفويض عشوائية في حدث GAS. يُتحقق من الحجم والشكل قبل المعالجة، مع مراعاة
  تخفيض البيانات وإخفاء محتوى الطلب من الأخطاء.
- الطابع الزمني الذي يقدمه العميل ليس ساعة موثوقة أو سجلًا للمطالبة، ولا يكفي للمصادقة أو
  لإثبات انتهاء عملية. لا يمنح انقضاؤه حق تحرير المطالبة. ينبغي اختبار فروق الساعة والقراءات
  القديمة والبعيدة، وتحديد سياسة مستقلة بدل افتراض نافذة آمنة.

## الحاجز المقترح للـnonce وحدوده

1. فشل المصادقة أو شكل الطلب يتوقف قبل لمس Requests أو بدء عملية حجز. لا يُستنتج فشل المصادقة
   من تعذر قراءة nonce؛ وينبغي مراجعة عدم كشف حالة nonce لطرف غير مصرح له.
2. لا يكفي فحص عدم وجود nonce دون قفل ثم كتابته: قراءتان متزامنتان قد تريان الغياب. يمكن رفض
   التكرار المرصود في فحص أولي بعد المصادقة، لكن الغياب الأولي لا يفوض الكتابة؛ يلزم فحص وحفظ
   تحت قفل قصير يلتزم به جميع كتّاب السجل، واختبار إعادة القراءة والأخطاء. لذلك لا يمكن عمومًا
   ضمان رفض **كل** تكرار دون أخذ قفل، خصوصًا عند المنافسة.
3. Script Lock يغطي التنفيذات المتعاونة في المشروع نفسه فقط، وليس تحرير Sheets الخارجي أو مشروعًا
   آخر. لا يُحتفظ به أثناء Calendar أو الشبكة. لا يثبت `flush()` معاملة ذرية بين nonce وRequests
   وCalendar، أو نتيجة كتابة ألقت استثناءً. فشل القراءة أو نتيجة الكتابة الملتبسة يعني
   `NONCE_STORAGE_UNKNOWN`، ومنع متابعة تلقائية وإحالة لمراجعة؛ لا تُعاد العملية تلقائيًا.
4. رفض تكرار nonce يمنع إعادة المحاولة في البديل المقترح لكنه لا يثبت نتيجة المحاولة الأولى.
   سجل `TrialNonces(nonce_id, consumed_at)` وحده لا يربط nonce بصف الطلب أو claim، ولا يثبت النية
   أو عدم وجود حدث. يلزم تصميم ارتباط موثوق ومراجعة عمر الاحتفاظ وتعارض الكتابات قبل التنفيذ.

## الردود المقترحة

يُقترح إرجاع JSON عبر `ContentService.createTextOutput()` للحالات التي يتحكم فيها المعالج، مع
فحص العميل للجسم لا الاكتفاء بـHTTP 200. لا يُفترض أن ContentService يسمح بتحديد status أو
ترويسات HTTP مخصصة؛ كما قد تقع أخطاء المنصة أو إعادة التوجيه خارج المعالج فلا تكون JSON أصلًا.
يجب اختبار معالجة إعادة التوجيه وعدم تسريب المصادقة قبل أي استخدام حقيقي.

أمثلة دلالية، لا عقد API منشور:

```json
{"auth_status":"AUTHENTICATED","process_status":"REJECTED_DUPLICATE_NONCE","original_result":"UNKNOWN"}
{"auth_status":"AUTHENTICATED","process_status":"SUSPENDED","reconciliation_code":"NONCE_STORAGE_UNKNOWN"}
{"auth_status":"AUTHENTICATED","process_status":"SUSPENDED","reconciliation_code":"LEDGER_TIMING_DRIFT_SUSPECT"}
```

لا يُجمع رفض التكرار مع `NONCE_STORAGE_UNKNOWN` باعتبارهما دليلين متلازمين: التكرار يتطلب
مشاهدة موثوقة، والفشل الملتبس لا يثبت التكرار. الاستجابات لا تكشف nonce أو سرًا أو تفاصيل المريض.

## مراجعة بشرية وتوافر

التحذير المحلي في `staff-warning-model.js` يعرض نصوصًا ثابتة فقط؛ لا يحمي مسارات التطبيق ولا
يسجل عزلًا أو يفوض مسؤولًا. يلزم لاحقًا تصميم مصادقة للموظف وحظر دائم موثوق لجميع الكتاب وقراءة
Requests وCalendar ومراجعة أخطاء القراءة قبل واجهة حقيقية. لا تحذف الأحداث أو تطهر البيانات أو
تحرر المطالبة تلقائيًا، ولو بسبب المهلة. التحرير البشري الآمن نفسه تصميم واختبارات منفصلة.

تتطلب البروفة الفعلية ثلاث جولات مستقلة، كل منها 10 طلبات `fetchAll` حقيقية لنفس الفترة بهويات
اختبار مختلفة، منفصلة عن حقن الأعطال، مع فحص النتائج والصفوف والتقويم. لا تثبت اختبارات الذاكرة
التزامن الحقيقي، ولا تُغيّر سياسة قبول عدة طلبات معلقة إلى نجاح طلب واحد في مرحلة التقديم ضمنًا.
