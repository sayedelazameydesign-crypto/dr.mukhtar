# آلة الحالات — الحجز والدور

> الحالات القائمة اليوم موجودة فعلًا في `Code.gs`: `REQUESTED`, `PENDING_APPROVAL`,
> `RESCHEDULED`, `CONFIRMED`, `CANCELLED`, `COMPLETED` (تُقرأ في `app.js` `statusText`).
> ما يلي يوسّعها دون كسر أي شيء قائم.

## 1 · حالات الحجز

```
                 ┌──────────────────────── CANCELLED ◄────── (أي حالة مفتوحة، بصلاحية)
                 │                              ▲
REQUESTED ──► PENDING_APPROVAL ──► CONFIRMED ──► CHECKED_IN ──► IN_CONSULTATION ──► COMPLETED
     │                │                │             │
     │                │                │             └──► NO_SHOW (لم يحضر بعد النداء)
     │                │                └──► RESCHEDULED ──► (يعود PENDING_APPROVAL)
     │                └──► RESCHEDULED
     └──► REJECTED (رفض صريح بسبب مكتوب)
```

| الحالة | المعنى للمريض | مَن يملك الانتقال | قيود |
| --- | --- | --- | --- |
| `REQUESTED` | «طلبك وصل، لم يُراجَع» | النظام | لا حدث تقويم |
| `PENDING_APPROVAL` | «بانتظار تأكيد العيادة» | النظام | الفتحة كانت متاحة لحظة الإرسال (`slot_verified`) |
| `CONFIRMED` | «مؤكد» | طبيب/مدير/استقبال بإعداد | **يُنشأ حدث Calendar أولًا** ثم الحالة |
| `RESCHEDULED` | «اقترحنا وقتًا بديلًا» | طبيب/استقبال/مدير | يمكن للمريض القبول (موجة ٢) |
| `CHECKED_IN` | «سجّلنا حضورك» | استقبال | ينشئ `queue_ticket` |
| `IN_CONSULTATION` | «الطبيب معك الآن» | طبيب | |
| `COMPLETED` | «انتهت الزيارة» | طبيب | يفتح التقييم وموعد المتابعة |
| `NO_SHOW` | «لم تحضر» | استقبال آليًا بعد نداء + مهلة | يُسجَّل السبب |
| `CANCELLED` | «ملغي» | الجميع بصلاحية | لا حذف للصف |
| `REJECTED` | «لم نتمكن من قبوله» | استقبال/مدير | بسبب مكتوب يُعرض للمريض |
| `EXPIRED` | «انتهت مهلة العرض البديل» | النظام (مؤقت) | فقط على عروض قائمة الانتظار |

### قواعد لا تُكسر
1. **لا `CONFIRMED` بلا حدث تقويم.** (القائم ينفّذها: الحدث أولًا ثم الحالة، `Code.gs:395-411`.)
2. **لا حذف صف حجز أبدًا** — الإلغاء حالة، لا حذف.
3. **كل انتقال مسجَّل** في `booking_status_history` (واليوم في `Audit`).
4. **`COMPLETED` لا رجعة فيه** إلا بتصحيح مسجَّل بسبب (§F8).

## 2 · حالات الدور (queue_ticket.stage)

الحالات السبعة التي وصفتها في الوحدة ٤ تُشتق هكذا — **بلا تكرار حالة**:

| ما يراه المريض | المصدر |
| --- | --- |
| «تم تأكيد الحجز» | `booking.status = CONFIRMED` |
| «تم تسجيل الوصول» | `queue_ticket.stage = WAITING` + `booking.CHECKED_IN` |
| «في انتظار الطبيب» | `stage = WAITING` و`called_at` فارغ |
| «الطبيب يستقبل الحالة الحالية» | هناك `stage = IN_ROOM` لطبيب آخر في نفس الطابور |
| «اقترب دورك» | ترتيب الدور ≤ ٣ |
| «دخلت إلى الكشف» | `stage = IN_ROOM` |
| «انتهت الزيارة» | `booking.status = COMPLETED` |

```
WAITING ──► CALLED ──► IN_ROOM ──► DONE
   │           │
   │           └──► SKIPPED (لم يجب بعد مهلة → يعود WAITING مرة واحدة)
   └──► LEFT (غادر قبل النداء)
```

### حساب الوقت التقديري (يُعرض كمدى لا كرقم)
```
estimate = Σ (duration_min للخدمات التي أمامه) ÷ عدد الأطباء المتاحين
يُعرض: «بين ٢٥ و٤٠ دقيقة» — لا «٣٢ دقيقة»
```
**السبب:** وعد دقيق لمدة الانتظار أكذوبة تتكرر كل ٥ دقائق. المدى صادق حتى يتحرك الطابور.

## 3 · قواعد الأولوية (لا تُترك للاجتهاد)

| الحالة | الأولوية | من يقرر |
| --- | --- | --- |
| حجز مؤكد ووصل في وقته | ترتيب `time` | النظام |
| وصول مبكر | مكانه حسب وقته لا حسب وصوله | النظام |
| walk-in | بعد المحجوزين | استقبال |
| «عاجل» بطلب العيادة | أول الطابور | **طبيب أو مدير فقط** + سبب مكتوب |
| طفل/رضيع بانتظار طويل | تنبيه للطبيب، لا قفز تلقائي | الطبيب |

> لا يجوز للنظام أن يعيد ترتيب المرضى بحجة «ذكاء» — قرار سريري ليس من اختصاص الكود.
