## ١. الجواب المباشر عن G23 (السؤال الذي لم يُحسم)

**ما يغلق G23 ليس تمرين B5.** B5 يُثبت تشغيل التطبيق على حساب Google حقيقي، وهو يخصّ G1/G14.
G23 نوعها مختلف: **سلوك غير مُتحقَّق منه في workflow** — أي أن `ai-repair.yml` و`ci-error-triage.yml`
كانا موجودين على فرع الـPR فقط، وGitHub يرفض `gh workflow run` لـworkflow غير موجود على الفرع الافتراضي.

بعد الدمج صار المانع التقني **زائلًا**: الوصف الحالي للفجوة لم يعد صحيحًا حرفيًا. لذلك يُعاد تقييمها
من الآن إلى أحد احتمالين:

| الاحتمال | متى | الدليل |
| --- | --- | --- |
| **G23 تُغلق** | تشغيلان مكتملان: `CI error triage` بـ`run_id` حقيقي أنتج أثرًا، و`AI repair` بـ`dry_run=true` انتهى بلا كتابة | رابط كل تشغيل + `conclusion` + وجود الأثر |
| **G23 تُعاد صياغتها** | إن كشف التشغيل عيبًا (مثلًا: التصنيف يحتاج صلاحية لا يملكها) | نصّ العيب + الفجوة الجديدة المفتوحة مكانها |

**الأوامر (أنا أستطيع تنفيذها، ولا تحتاج منك شيئًا):**

```bash
gh workflow run ci-error-triage.yml -f run_id=<id تشغيل فاشل حقيقي>
gh run list --workflow=ci-error-triage.yml --limit 1 --json databaseId,conclusion
```

المشكلة الوحيدة: نحتاج **تشغيلًا فاشلًا حقيقيًا** لنتتبعه. تُصنَّع هذه الحالة بأمان على هذا الفرع
(كوميت اختبار يفشل ثم يُلغى) — لا على `main`. سأفعل ذلك وأعرض الناتج، أو أنتظر موافقتك.

### ٣.١ الملف الذي يُملأ فعلًا (لا ابتكار جديد)

المستودع يملك أداة مكتوبة لهذا بالضبط: `scripts/rehearsal-checklist.json` (١٨ خطوة) وتحقّقها
`node scripts/check-rehearsal.js --strict`. الحالة الآن، بلا تجميل:

```
node scripts/check-rehearsal.js
— بروفة Google —
  · S1: 0/5 · S2: 0/1 · S3: 0/2 · S4: 0/7 · S5: 0/1 · S6: 0/2
  المجموع: 0/18 خطوة بدليل
  الفجوات G1 وG14 تبقى «غير مُتحقَّق» حتى تُملأ الأدلة.
```

- **S4** (٧ خطوات) هي B5.1–B5.7، و`closes: ["G1"]` صريح في الملف.
- **S5** هي `closes: ["G14"]`.
- `--strict` يرفض أي خطوة «منجزة» بلا دليل مكتوب — أي أنه **بوابة**، لا قائمة أمنيات.

أي: G1 وG14 لا تُغلقان بتقرير منّي، بل بملف تُكتب فيه الأدلة ثم يمرّ على `--strict`.

## ٥. تقرير الجهوزية: تثبيت `jsdom` بشكل قابل لإعادة الإنتاج

المشكلة الحقيقية اليوم: `/tmp` يُمسح بين الجلسات، فتمريرة `--require-jsdom` تنجح أو تفشل حسب
**وجود أداة**، لا حسب **حالة المستودع**. هذا يجعل الفحص غير حاسم.

الحل: `package.json` + `package-lock.json` مُثبَّتان في المستودع (نسخة `jsdom` مقفلة)، والفحص يصبح:

```bash
npm ci
node scripts/readiness-report.js --offline --require-jsdom
```

`node_modules/` يبقى مُستثنى من Git (وهو كذلك الآن). CI يفعل الشيء نفسه بدل `npm i --no-save`.
