# مواصفة أعطال الحجز التشغيلي — تجربة محلية فقط

هذه المواصفة لا تصف مسار الموافقة المستخدم في `Code.gs` ولا تغيّر مخطط Sheets.
`scripts/operational-slot-model.js` نموذج قرارات معزول؛ و`scripts/test-operational-slot-faults.js`
تجربة متسلسلة في الذاكرة تستعمله مع بدائل مكتوبة. لا تستدعي Google أو شبكة، ولا تختبر
`SpreadsheetApp.flush()` أو `LockService` الفعليين. فشل المحاكاة استثناء داخل العملية، وليس
إثباتًا لسلوك توقف عملية GAS أو متصفحات متزامنة.

## فرضيات وحدود مهمة

- يستخدم البديل سجل nonce وصف حجز منفصلين، ويضع معرّف المطالبة داخل الحالة الوهمية
  `UNDER_CREATION::<UUID>`؛ لا يثبت ذلك توافقه مع معالجات `Requests` الحالية. الحالة الجديدة
  غير مدعومة في مسارات التطبيق الفعلية، ولا يجوز اعتمادها هناك قبل تصميم توافق شامل. لا توجد
  مصادقة أو نقطة HTTP أو سجل nonce حقيقي في هذه التجربة.
- كل كتابة وflush في البديل لها حالتا فشل: لم تُحفظ الكتابة، أو حُفظت رغم الخطأ. لا تفترض
  التجربة أن `flush` معاملة ذرية، ولا أن أيًا من الحالتين يحاكي بالتحديد سلوك Google.
- تستهلك التجربة nonce قبل الحجز؛ عندما تُحفظ الأولى ولا تُحفظ الثانية قد يتعذر تكرار نفس
  nonce رغم عدم وجود حجز. وعندما لا يُحفظ nonce قد يُقبل مجددًا. لا يوجد ضمان منع إعادة حقيقي.
- اختبارات البديل لا تتحقق من فحص Calendar قبل الإنشاء، أو تعارض تعديل تقويم خارجي بعد
  الفحص، أو صلاحيات الموظف، أو القراءات الفاشلة من Sheets، أو المنطقة الزمنية وDST، أو تغييرات
  الإلغاء والنقل والإغلاق المتزامنة. هذه شروط لازمة لتصميم لاحق، وليست منجزة هنا.
- نتيجة `UNKNOWN` لا تُثبت أن صف `NEEDS_REVIEW` قد كُتب. لا يوجد تحرير يدوي أو حذف تلقائي،
  ولا إعادة محاولة تلقائية في التجربة. التكرار اللاحق في الاختبار استدعاء صريح لفحص الحظر.

## حالات الحقن

| موضع التوقف في البديل | معيار الاختبار |
| --- | --- |
| القفل الأول | لا كتابة ولا اتصال تقويم وهمي. |
| قراءة أو كتابة أو flush للـnonce، قبل الأثر أو بعده | `NONCE_STORAGE_UNKNOWN` لا تعني فشل التفويض؛ لا استدعاء تقويم، واستهلاك nonce يختلف بين الفرعين. رفض التكرار لا يحسم المحاولة الأولى. |
| كتابة أو flush للحجز، قبل الأثر أو بعده | لا استدعاء تقويم؛ إذا حُفظ الحجز فإنه يحجب مرجعًا منافسًا. لا نفترض أن nonce والحجز معاملة واحدة. |
| بعد حفظ الحجز وقبل الإنشاء | يبقى الحجز محجوبًا، بلا حدث ولا تحرير تلقائي. |
| إنشاء الحدث قبل الأثر أو بعده، أو فشل القراءة | يظل الحجز محجوبًا؛ قد يوجد الحدث رغم الخطأ؛ لا حذف أو إنشاء إضافي عند فحص الحظر. |
| القفل الثاني أو كتابة/flush التأكيد | تبقى الحالة غير محسومة؛ يحتفظ البديل بالحدث، وتكون الحالة إما حجزًا محجوبًا أو تأكيدًا محفوظًا حسب فرع العطل. |

## نماذج الوقت والسجل المنفصلة

- `cairo-slot-model.js` يحول مدخلات نصية مقيدة عبر Node/ICU إلى فترات بنهايات حصرية؛ المدد
  مُدخلة في الاختبار وليست افتراضًا عن إعداد العيادة الفعلي. الأوقات غير الموجودة أو المكررة
  عند انتقال DST تُرفض بدل التخمين. لا يختبر خلايا Sheets أو محرك GAS أو تغير بيانات المنطقة.
- `trial-ledger-model.js` يتحقق من شكل ٣٠ سجلًا اصطناعيًا لـ٣ جولات × ١٠ محاولات، مع طوابع
  milliseconds اختيارية وقيم مجهولة. يمنع حقولًا إضافية وخلط نوع تجربة الأعطال في سجلات التنافس؛
  لا ينشئ ورقة ولا يجري اختبارًا ولا يثبت التداخل. `matchingEventCount` هو عدد الأحداث المطابقة
  لمرجع المحاولة بعد قراءة ناجحة؛ `null` يعني غير معروف، ولا يُغني عن عدّ أحداث الفترة كاملة.
- يجب أن تبقى اختبارات التنافس الفعلية، إذا اعتُمدت لاحقًا، في مشروع اختبار مستقل وعلى بيانات
  وهمية، وأن تنفصل عن حقن الأعطال واختبارات النقل والإلغاء. التحقق من الشكل ليس دليلًا على تنفيذها.

تشغيل: `node scripts/test-operational-slot-faults.js`, `node scripts/test-cairo-slot-model.js`,
`node scripts/test-trial-ledger-model.js`. تُشغَّل أيضًا ضمن `npm test` وCI. هذه أدلة على سلوك
البدائل فحسب، وليست دليل بروفة `fetchAll` أو جاهزية إنتاج.
